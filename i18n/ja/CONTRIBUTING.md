# 参加要項 — draft

**10の質問** は、異論や反論を含むさまざまなアイデアを歓迎します。

[English](../../CONTRIBUTING.md)

新しい質問を思いついたとき、既存の10問に疑問を感じたとき、あるいは翻訳してずれに気付いたときは、そのまま議論に持ち込んでください。候補を増やすことも、削ることも、順番を変えることも、このプロジェクトの作業です。

貢献の例:

- 新しい質問を提案する
- 10問のうち1つを置き換える、または順序を変える
- 質問に隠れている前提を指摘する
- 2つの質問が実質的に重複していることを示す
- どの言語であれ、より明確な表現を提案する
- 新しい言語版を加え、翻訳によって何が変わるかを説明する
- 通信、認知、時間、因果、対立、ネットワーク、社会組織などに関する背景資料を提供する
- 仮想的な接触シナリオを使って10問を検証する

## 質問を提案するとき

質問そのものに加えて、可能であれば以下も検討してください。

1. **何を知りたいのか** — 表面上の文言ではなく、その答えから判断したいこと、解釈可能なこと
1. **何を前提としているのか** — 個体、集団、時間、因果、意図など、質問が成立するために共有されている必要がある概念
1. **なぜその順位なのか** — 10問の中に入れるなら、より後ろの質問より先に聞く理由
1. **ニュアンスの違い** — 言語や文化によって意味がずれる箇所があれば、その点も明示する

すべてを埋める必要はありません。ただし「面白そうだから」だけでは優先順位を判断できません。何を知るための質問なのかが分かれば、候補として比較できます。

質問は深遠そうに聞こえる必要もありません。「お酒を飲みますか」のような短い質問でも、娯楽、ストレス、儀礼、依存、自己変容など複数の論点に接続できるなら、十分に検討する価値があります。

## 質問データとマージ条件

質問は `questions/Q-0000.yml` 形式のファイルに置きます。人間が直接読むことを優先し、YAML として同じ意味なら特定の整形スタイルは強制しません。

提案時点では、質問文が1言語だけでも構いません。それだけで pull request を開き、議論を始めたり、他の参加者に翻訳を頼んだりできます。

ただし `main` にマージする時点では、英語と日本語の両方 (`text.en` と `text.ja`) が必要です。これは公開時の要件であって、どちらかを基準言語とするという意味ではありません。自分だけで両方を書けない場合は、提案を止めるのではなく翻訳の協力を求めてください。

このほか、質問ID、ファイル名、index などの機械可読な情報については、内部整合性を保つためのチェックを行う予定です。validation はデータが利用可能かどうかを確認するためのもので、YAML の見た目を一つに揃えるためのものではありません。

将来の公開用生成物は `dist/` 以下に出力します。`dist/` は build output であり、リポジトリには commit しません。

## 言語

このプロジェクトに基準となる単一の言語はありません。

新しい言語版を作るときは、英語や日本語の文を機械的に置き換えるだけでなく、できればその言語で意味がどう変わるかも示してください。言語間のずれは単なる翻訳上の不一致とは限りません。質問そのものが人類の多様性を表現する可能性があります。

## 議論の進め方

SFを書くつもりで自由な発想を楽しんでください。ユーモアや遊び心も歓迎します。ただし、その質問から何を知り得るのかは真面目に検討してください。

もちろん他者を卑下・攻撃するような言動は厳禁です。節度あるコミュニケーションを期待します。

## スナップショット

日付付きスナップショットは、その時点での編集判断を保存するものです。完成を宣言するものではありません。

あるスナップショットに入らなかった提案も、それだけで却下にはなりません。候補として残り、後の議論で順位が変わることがあります。
